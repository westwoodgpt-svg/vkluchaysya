## 1. Что это

**«Включайся» — Портал идей** — внутреннее приложение для сбора идей и
предложений сотрудников Фонда по улучшению работы. Сотрудник заполняет
пошаговую форму, а приложение создаёт в CRM Битрикс24 **лид**
«Идея № N — <название>» и раскладывает ответы по отдельным полям карточки.

- Заголовок страницы: **«Есть идея!»**, бейдж «✦ Программа «Включайся»».
- Подзаголовок: «Любое предложение по улучшению работы Фонда — важный шаг вперёд
  для всей нашей сплоченной команды».
- Работает как **локальное приложение Битрикс24**, открывается внутри портала
  во фрейме (iframe).

## 2. Сценарий пользователя

### 2.1. Открытие
1. Сотрудник открывает приложение в Битрикс24 (меню портала или QR-код).
2. В шапке индикатор связи: **«Битрикс24 подключен»** (зелёный, во всплывающей
   подсказке — домен портала) или **«Нет связи с Битрикс24»** (серый).
3. Приложение автоматически подставляет **ФИО, должность и отдел** текущего
   пользователя (методы `user.current` и `department.get`) — на шаге 1
   появляется отметка об автозаполнении.

### 2.2. Форма — 3 шага
Вверху — «Шаг N из 3» и прогресс-бар «X из 10 полей заполнено (%)».

**Шаг 1. Информация об авторе** (все обязательные)

| Поле | Подсказка |
|---|---|
| ФИО * | «Иванов Иван Иванович» |
| Должность * | «Главный специалист» |
| Отдел * | «Департамент развития» |

**Шаг 2. Суть Вашей идеи**

| Поле | Тип / варианты |
|---|---|
| К какой категории относится Ваша идея? * | Атмосфера и комфорт в офисе · Улучшение в процессах · Корпоративная культура |
| Название идеи * | текст, пример: «Оптимизация системы хранения архивных документов» |
| Опишите текущую ситуацию * | «Как процесс устроен сейчас? В чем основное затруднение…?» |
| Опишите Вашу идею * | «Что конкретно предлагаете сделать? Как изменится процесс…?» |
| Ссылка на дополнительные материалы | необязательно (Диск, схема, презентация, ТЗ) |

**Шаг 3. Параметры внедрения** (все обязательные)

| Поле | Варианты (значение → подпись) |
|---|---|
| Требуются ли финансовые затраты? * | `да` → «Да, требуются» · `нет` → «Нет, без затрат» |
| Для кого эта идея? * | только мне · отдела · блока · всего Фонда |
| Готовы ли Вы самостоятельно внедрить идею? * | `да` → «Да, полностью готов» · «Нужна команда от Фонда» · «Нужны внешние исполнители» |

Если отдельные поля CRM не созданы (нет прав администратора CRM), на шаге 3
показывается жёлтая плашка **«Отдельные поля CRM пока не созданы»**: идея всё
равно сохранится — одним текстом в комментарий лида.

### 2.3. Отправка
- Экран успеха: **«Идея успешно отправлена!»**, порядковый номер идеи
  (`№ N`) и ID лида (`LEAD_<id>`), кнопка «Отправить еще одну идею».
- После отправки форма очищается, но ФИО/должность/отдел сохраняются.
- При ошибке — красная плашка с текстом ошибки (по умолчанию «Не удалось
  отправить идею в CRM Битрикс24…»).

### 2.4. История
Вкладка **«История (N)»** / «История предложений» (в мобильном меню):
- список идей, отправленных **с этого браузера** (хранится в `localStorage`,
  ключ `ideas_archive`, новые сверху);
- поиск по названию, автору, отделу и сути идеи;
- фильтр по категориям (Все категории / Атмосфера и комфорт / Процессы /
  Корпоративная культура);
- карточка деталей: дата, «Об авторе», «Суть предложения», «Материалы идеи»,
  «Разметка ячеек в CRM Битрикс24» (финансы, аудитория, готовность).

> История — локальная: на другом устройстве/браузере она пуста. Источник
> правды — лиды в CRM.

## 3. Что попадает в CRM

Создаётся лид методом `crm.lead.add`:

| Поле лида | Значение |
|---|---|
| `TITLE` | `Идея № {N} — {Название идеи}` |
| `LAST_NAME` / `NAME` / `SECOND_NAME` | ФИО, разбитое по пробелам (1-е слово — фамилия, 2-е — имя, остальное — отчество) |
| `POST` | Должность |
| `ASSIGNED_BY_ID` | **1324** — ответственный (захардкожен в `src/App.tsx`; до 2026-07-30 был 1220) |
| `SOURCE_ID` | `"6"` (Веб-сайт / виджет) |
| `SOURCE_DESCRIPTION` | `Включайся` |
| `COMMENTS` | Полный текст идеи в читаемом виде — **всегда**, как страховка |
| `UF_CRM_IDEA_*` | Ответы формы по отдельным полям (см. ниже), если поля найдены |

### 3.1. Пользовательские поля лида
8 строковых полей, созданы приложением автоматически 2026-07-14:

| Код | Название | Поле формы |
|---|---|---|
| `UF_CRM_IDEA_DEPT` | Включайся: Отдел | department |
| `UF_CRM_IDEA_CAT` | Включайся: Категория идеи | category |
| `UF_CRM_IDEA_SIT` | Включайся: Текущая ситуация | currentSituation |
| `UF_CRM_IDEA_DESC` | Включайся: Суть идеи | idea |
| `UF_CRM_IDEA_LINK` | Включайся: Ссылка на материалы | materialsLink |
| `UF_CRM_IDEA_FIN` | Включайся: Финансовые затраты | needFinance |
| `UF_CRM_IDEA_IMPL` | Включайся: Готовность внедрить | implementation |
| `UF_CRM_IDEA_AUD` | Включайся: Целевая аудитория | audience |

Название идеи в отдельное поле не пишется — оно в `TITLE`.

### 3.2. Автоматика полей (`ensureCrmFields` в `src/App.tsx`)
Выполняется при загрузке **и перед каждой отправкой**:
1. `crm.lead.fields` — получить все поля лида.
2. Для каждого из 8 полей найти совпадение **по коду** или **по точному
   названию** «Включайся: …» (так подхватываются поля, созданные вручную с
   автокодом вида `UF_CRM_17…`).
3. Недостающие создать через `crm.lead.userfield.add` (нужны права
   администратора CRM; у рядовых сотрудников молча не получится).
4. Построить маппинг «поле формы → код CRM»; ненайденные остаются на
   `COMMENTS`. Маппинг кешируется в `localStorage` (`crm_field_mapping`).

Ручной настройки маппинга в интерфейсе нет (вкладка «Интеграция CRM» удалена).

### 3.3. Нумерация идей
`N` = количество лидов, у которых в названии есть «Идея №»
(`crm.lead.list` с фильтром `%TITLE`) + 1. Если запрос не удался — длина
локальной истории + 1.

## 4. Архитектура

### 4.1. Стек
- **Фронтенд:** React 19, TypeScript, Vite 6, Tailwind CSS 4, `motion`
  (анимации), `lucide-react` (иконки). SPA.
- **Бэкенд:** Vercel Serverless Functions (`api/`).
- **Интеграция:** Bitrix24 JS SDK (`https://api.bitrix24.com/api/v1/`,
  подключён в `index.html`) + серверный REST-прокси как запасной путь.
- Стиль UI — «эппловый»: фон `#F5F5F7`, текст `#1D1D1F`, акцент `#00AEEF`.

### 4.2. Структура репозитория
```
api/
  index.ts      — обработчик корня "/" (GET и POST от Битрикс24), отдаёт SPA
  rest.ts       — POST /api/rest: прокси к https://{domain}/rest/{method}.json
  health.ts     — GET /api/health → {status:"ok", time}
src/
  main.tsx      — точка входа React
  App.tsx       — шапка, вкладки, авторизация, автозаполнение, ensureCrmFields, отправка лида
  types.ts      — IdeaForm, FieldMapping, ArchiveItem, BitrixAuth, CrmField
  utils/bx24.ts — работа с SDK: whenBx24Ready, getAuth, callMethod, fetchLeadFields,
                  createLeadUserField, adjustIframeHeight, RECOMMENDED_FIELDS
  components/
    LeadForm.tsx — 3-шаговая форма, валидация, прогресс, экран успеха
    Archive.tsx  — локальная история, поиск, фильтр, карточка деталей
  index.css
index.html      — подключает Bitrix24 JS SDK
vercel.json     — сборка и rewrite "/" → "/api"
server.ts       — старый Express-сервер (AI Studio / локальный dev), в проде не используется
metadata.json   — метаданные AI Studio
NOTES.md        — память проекта
qr-vkluchaysya.png — QR-код на приложение в портале
```

### 4.3. Как Битрикс24 открывает приложение
1. Битрикс24 грузит iframe **POST-запросом** на «Путь обработчика»
   (`https://vkluchaysya.vercel.app/`) с `AUTH_ID`, `REFRESH_ID`, `DOMAIN`,
   `MEMBER_ID`, `PLACEMENT`, … и добавляет к URL свои `APP_SID`, `DOMAIN`,
   `PROTOCOL`, `LANG`.
2. `vercel.json` переписывает `/` → `/api` → `api/index.ts`.
3. `api/index.ts` читает собранный `dist/app.html` и, если есть параметры
   авторизации, внедряет их в `<head>` как `window.__BX_AUTH__` (с экранированием
   `<`). **Никакого редиректа** — иначе теряется `APP_SID` и SDK не проходит
   handshake.
4. При сборке `dist/index.html` переименовывается в `dist/app.html`, чтобы
   статический файл не перехватывал корень и функция вызывалась всегда.

### 4.4. Авторизация на клиенте (`getAuth`)
Сначала `whenBx24Ready()` ждёт handshake SDK (до 4 с, опрос каждые 100 мс),
вызывает `BX24.init` и `BX24.installFinish()` (без него у сотрудников без
админки было «Приложение ещё не установлено до конца»). Затем источник токена
по приоритету:
1. `BX24.getAuth()` — живой токен SDK (обновляется самим SDK);
2. `window.__BX_AUTH__` — внедрён сервером из POST;
3. URL-параметры `AUTH_ID`/`DOMAIN` (наследие редирект-схемы);
4. `localStorage` (`bx24_auth`) — последняя успешная авторизация.

### 4.5. Вызов методов (`callMethod`)
Если SDK доступен — `BX24.callMethod`, иначе — `POST /api/rest`
(`{method, domain, auth, params}`), который проксирует запрос на портал.

Используемые методы REST: `user.current`, `department.get`, `crm.lead.fields`,
`crm.lead.userfield.add`, `crm.lead.list`, `crm.lead.add`.
Высота фрейма подстраивается через `BX24.fitWindow()`.

### 4.6. Хранилище браузера
| Ключ `localStorage` | Что хранит |
|---|---|
| `ideas_archive` | локальная история отправленных идей |
| `crm_field_mapping` | кеш маппинга полей формы на поля CRM |
| `bx24_auth` | последняя авторизация |

## 5. Сборка, запуск, деплой

- **Прод:** Vercel, `buildCommand: vite build && mv dist/index.html dist/app.html`,
  `outputDirectory: dist`. Каждый push в `main` → автодеплой.
- **Локально:** `npm install`, `npm run dev` (запускает старый `server.ts` на
  порту 3000 с Vite в middleware-режиме). Учтите: `server.ts` всё ещё делает
  302-редирект на POST — для реальной работы внутри Битрикс24 это поведение
  неверно, ориентир — `api/index.ts`.
- **Проверка типов:** `npm run lint` (`tsc --noEmit`). Тестов нет.
- **Переменные окружения:** в проде не нужны. `.env.example` (`GEMINI_API_KEY`,
  `APP_URL`) — наследие шаблона AI Studio; Gemini в коде не используется.

### Настройка в Битрикс24 (для администратора)
1. Локальное приложение с путём обработчика `https://vkluchaysya.vercel.app/`
   и правами на CRM и пользователей (`crm`, `user`, `department`).
2. Один раз открыть приложение **под администратором CRM** — создадутся поля
   и выполнится `installFinish`.
3. В карточке лида: «Выбрать поле» → отметить поля «Включайся: …» → сохранить
   вид «для всех». Иначе заполненные поля не видны в карточке.

## 7. Известные ограничения и грабли

1. **Не возвращать редирект в `api/index.ts`** — сломается BX24 SDK.
2. **Создание полей требует прав администратора CRM.** У сотрудника без прав
   данные идут только в `COMMENTS`.
3. **Поля не видны в карточке**, пока их не добавить в раскладку (см. §5).
4. **Поля есть только у лидов** — при конвертации в сделку не переносятся.
5. **QR-код** открывает браузер с формой входа: коробочный домен не
   перехватывается мобильным приложением Битрикс24, deep-link невозможен.
   Вход в браузере нужен один раз.
6. **Нумерация не атомарна:** при одновременной отправке двумя людьми номера
   могут совпасть; удаление/переименование лидов тоже сдвигает счёт.
7. **История локальная** (на устройство/браузер), не общая.
8. **Ответственный (1324) захардкожен** — смена требует правки кода и деплоя.
9. **`/api/rest` — открытый прокси:** принимает любой метод и любой домен без
   проверки; стоит ограничить доменом портала и списком методов.
10. Перед каждой отправкой повторно запрашиваются поля CRM (лишние вызовы, зато
    маппинг всегда актуален).

## 8. Технический долг / мусор от шаблона
- `README.md` описывает шаблон AI Studio, а не реальное приложение.
- `package.json`: имя `react-example`; зависимости `@google/genai`, `express`,
  `dotenv` в проде не используются.
- `server.ts` устарел (редирект-схема).
- `metadata.json` объявляет `MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API` — не используется.
- В `App.tsx` не используется константа `BG_SVG`; в `Archive.tsx` — проп
  `onClearArchive`.
